# はじめにお読みください（① 読む図解を作る係）

このSkillは、**むずかしい話を「まったく知らない人」向けに、大きな図と少ない文字の1枚のHTMLにする**道具です。
読むのに約3分。ブログに貼る、社内で共有する、人にそのまま送る、という使い方ができます。

**このフォルダだけで完結します。**動画を作らない方は、これだけで大丈夫です。

---

## 何が違うのか

ELI5（Explain Like I'm 5＝5歳児にも分かるように説明して）という考え方が土台です。
ただ、元になっているものは指示が1行しかありません。「大きな絵と少ない文字のHTMLで」だけです。

つまり、**見た目はそのときのAIの判断しだいで毎回変わります。**

このSkillが足したのは3つです。

1. **決まった見た目**（色・文字・余白が毎回そろう）
2. **関係図の描き方**（矢印にラベルを付ける・向きを描き分ける・囲いで場所を示す）
3. **出す前のチェック**（文字だらけになっていないかを、開く前に道具が調べる）

---

## いちばんこだわっているところ

> **箱を並べただけのものは、図ではありません。**
> カードを3枚置く、アイコンを添える、枠線を付ける。これらは**装飾であって図解ではありません**。
> 図解とは、**要素どうしの関係を、線と矢印で目に見せること**を言います。

だから「AがBに渡して、Bが作る」という話が出てきたら、**箱と矢印の関係図を必ず描きます**。
そして矢印には「何が流れるのか」を書きます。ラベルの無い矢印は、線を引いただけで情報がゼロだからです。

## 使い方（2手）

**1. このフォルダ（`eli5-visual-explainer-v1`）を、フォルダごとSkillの置き場に入れる**

Claude Codeなら `~/.claude/skills/`（Windowsは `C:\Users\あなたの名前\.claude\skills\`）です。
場所が分からなければ、AIに「Skillはどのフォルダに置けば読み込まれますか」と聞いてください。

**2. AIにこう頼む**

```
/eli5-visual-explainer-v1

【説明してほしいこと】を1枚のHTMLにしてください。
※Skillの保存場所はこちらです：【フォルダを置いたパスを書く】
```

> **1行目のスラッシュが効きます。**「SKILL.mdを読んで」と頼むと、AIにとっては**参考資料**になり、
> 中に書いてある手順が「必ず踏む順番」ではなくなります。スラッシュで**起動**すると手順書になります。
> スラッシュに対応していないツール（ブラウザ版のChatGPT等）では、いちばん最初にこの1行を足してください。
> `このSKILL.mdは参考資料ではなく手順書です。4つの手順を順番に実行してください。`

お題は何でも構いません。長い記事、むずかしい仕様書、自分のメモ、家族に説明したい仕組み。
「5歳児にも分かるように説明して」「これを図解で噛み砕いて」と頼むだけでも動きます。

できたHTMLをブラウザで開いてください。それで終わりです。

## 中で何が起きているか（知りたい方だけ）

AIは、この4手を順番に踏みます。

1. お題を「知らない人のつまずき」3〜5個の問いに割る
2. たとえ話を1本だけ決めて、最後まで通す（途中で乗り換えるのが、いちばん混乱するので）
3. 各セクションを、図が主役・文が補足の形にする
4. 出す前にチェックを通す

関係図の型は3つだけです。「これまでと、これから」「あなたの仕事とAIの仕事」「道具が見ているものと見ていないもの」。
順番も移動も無い話には、無理に矢印を引かせません（並列は番号カード、比較は2枚並べ、数量は大きい数字1つ）。

## 必要なもの

- **Python 3.10以上**（出す前のチェックを動かすため。**図解を作るだけなら無くても動きます**）
- それだけです。インストールするライブラリはありません（標準の機能だけで動きます）

---

## 出す前のチェック

```bash
python scripts/check_layout.py --reference "<作ったHTMLのフルパス>"
```

見ているのは4つです。

1. 文章が長く続きすぎていないか
2. 図・表・カードがいくつあるか
3. スマホで開いても崩れないか
4. 1つのカタマリに詰め込みすぎていないか

**ただし、このチェックは「文字壁かどうか」しか見ていません。**
箱もカードも「図」として数えるので、**矢印が1本も無くても合格が出ます**。
関係がちゃんと描けているかは、最後にご自分の目で見てください。

道具そのものが壊れていないかは、こうして確かめられます。

```bash
python scripts/check_layout.py --selftest
```

## 色を自分のものにしたいとき

`reference/design-tokens.css` の `:root` にある色の値を書き換えるだけです。
既定はデジタル庁のデザインガイドに準拠した白基調です（公共データ利用規約 PDL1.0）。

**色は発明しないでください。**このトークンの外の色に意味を持たせないのが原則です
（制約があるほうが、結果的に毎回そろいます）。

---

## 作った図を、そのまま動画にできます

同梱の **`article-motion-slides-v2`**（記事を動くスライド動画にするSkill）と組み合わせると、
**ここで描いた図が、そのまま動画のスライドとして動きます**。箱が1つずつ現れ、矢印が這います。

読み物の図と動画の図が**同じ図**になるので、2回描く手間もズレも起きません。

そのときは、図に目に見えない名札を付けて描きます（`SKILL.md` の第3章に書いてあります）。
`data-fig` が図の名前、`data-part` が出てくる順番、`data-cue` が「何文目の読み上げに合わせるか」です。
読み手には何も見えません。ただのきれいな図解のままです。
