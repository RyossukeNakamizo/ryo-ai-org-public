# Plan-First Gate

実行前に1往復だけ確認し、Go 後はノンストップで完走するための規律。
「推測で即走って3回間違える」より「計画確認1往復」のほうが総所要時間で速い、
という原則を機械化する。

## §1 非自明タスクの判定（いずれか1つで該当）

1. 触るファイルが3つ以上、または影響範囲が事前に確定できない
2. 非可逆操作を含む（削除・移動・上書き・履歴改変・外部送信）
3. 課金を伴う可能性がある
4. 新規の設計判断・アーキテクチャ選定を含む
5. 指示にゴールまたは完了基準が明示されていない
6. 指示が「最短で」「よしなに」等の解釈委任表現を含む

いずれにも該当しない軽作業はゲートなしで即実行してよい。
判定に迷ったらゲートを出す（過剰な1往復のコスト < 誤走のコスト）。

## §2 「最短」の解釈規定

「最短」は**手戻り込みの総所要時間最小**と解釈する。目先の手数最小ではない。
ゴール定義・完了基準・制約に欠落があるとき、推測で埋めて走ることを禁止する。
埋めた推測はゲート提示に【推測】ラベル付きで明示し、Go の判断材料にする。

## §3 ゲート提示の形式（5行以内・厳守）

実行開始前に以下を提示し、Go を待つ。

```
【Plan-First】
1. ゴール解釈: <何を達成すれば完了か。推測で補った箇所は【推測】を付す>
2. 完了基準: <検証可能な形で。テスト・成果物・状態>
3. 手順概要: <主要ステップのみ。3項目以内>
4. 影響範囲: <触るファイル・非可逆点・課金有無>
5. リスク: <外し得る解釈・盲点があれば1点>
```

- 5行に収まらない規模のタスクは、ゲートではなく計画分解
  （worker-delegation-protocol / 通常の計画立案）へ切り替える。
- Go の形式: 「Go」「OK」「進めて」等の明示応答。無応答は Go ではない。
- ユーザー がゲート内容の一部を修正して返した場合、修正を反映した解釈で実行する
  （全項目の再提示は不要。修正が根本的な場合のみ再ゲート）。

## §4 ゲートスキップ用の指示テンプレ（ユーザー 側）

以下の3項が埋まった指示はゲートを出さず即実行する（往復ゼロの最短ルート）:

```
ゴール=◯◯、完了基準=◯◯、制約=◯◯、あとは最短で
```

3項のうち一部のみ明示されている場合、欠けた項だけをゲートで確認する
（埋まっている項を聞き直さない）。

## §5 Go 後の規律

- Go 後は途中確認なしで完走する。中間報告のための停止をしない。
- 例外（Go 後でも必ず停止する）:
  1. 課金を伴う操作に到達した（課金実行規律: 見積・ETA・明示 Go が別途必要）
  2. 委任指示の絶対制約に抵触し得る操作に迷った（W-0713 判例: 照会して待つ)
  3. 実行中に自分の文脈理解と直前指示の矛盾・欠落の兆候を検知した
     （修理・続行を試みず中断して報告する）
  4. ゲート提示した影響範囲を超える変更が必要と判明した（差分だけ再ゲート）
- 完了報告では、ゲートで提示した完了基準に対する達成状態を対応させて報告する。

## §6 反例（このスキルが防ぐ失敗の型）

- 「最短で」を手数最小と解釈し、推測仕様で実装して3回差し戻される
- ゴール未確認のまま複雑な修理を開始し、依頼外の改修へ膨張する
- 確認を恐れて走らない／逆に全タスクで確認を挟んで速度が死ぬ
  （§1 の線引きと §4 のスキップ経路がこの両極を防ぐ）
